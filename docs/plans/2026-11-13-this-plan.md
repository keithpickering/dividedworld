# THIS, a note that points at a post's words: plan

Record, written 2026-11-13. Carries out `docs/plans/2026-11-13-this-design.md`. One PR from `main`.

Every task goes test first: write the failing test, record its red run, then the code. During a task, run only the
tests for the changed code (`npx vitest run <file>`, or `node --test <file>` for the rules' tests, as each file's
neighbors are run). Run `npm run typecheck` and `npm run build` once after the last task, with the tail in the PR. No
deployed database, bucket or connector is touched. This plan adds no migration and no SQL: a card reaches the database
through the instance's seed (`supabase/functions/_shared/seed.ts`, `instanceSeed`), and a play's configuration is
checked by the instance's rules at the edge (`supabase/functions/act/core.ts`, `runAction`).

**The layers.** Task 1 is engine (`engine/ui/bbcode/`) and names no instance and no card; the engine boundary check
(`tools/check-engine-boundary.mjs`) holds throughout. Every other task is Divided World's, carried in through
`CardRules`, `CardUi` and a `TextLayer`.

**The world.** The note, the play form and the receipt are the board (Verdana, the board's tokens, color only on the
game's own piece, which is the note). The mocks (`docs/research/2026-11-12-this/01-phone.png`, `02-desk.png`,
`03-look.png`, panel "A" and "Marker words") are the reference for how the highlight, the wedge, the arrow and the
handwriting look; where they and this plan disagree, this plan wins on what is decided and the mocks on how it looks.
The mocks draw the caster's words in capitals because Permanent Marker has no lowercase; that is the face, not a rule.

**Names used below.** The card's key is `this`. Its folder for screens is `instances/divided-world/ui/this/`, beside
`ui/laugh-track/`. Its classes begin `dw-this`.

## Task 1. A trail that stands (engine)

Model: sonnet

**Files:** `engine/ui/bbcode/layers.tsx` (`TextRun`, the header comment), `engine/ui/bbcode/render.tsx` (`Layered`,
`layeredText`, and wherever `Layered` is built), `engine/ui/bbcode/render.test.tsx` (the `a wrap run's trail` block,
lines 389 to 439).

Today `layeredText` draws a trail only when the stretch's own run ends there (`render.tsx`, the line under "The trail
follows the piece that ends the run's drawn words"), so a wrap run whose end lies under a higher run has none. The
design's section 5 adds an opt-in.

- `TextRun` gains `readonly stands?: true`, documented: "Its trail is drawn at the run's end whatever run is drawn
  there. Only a wrap run with a `trail` may set it."
- `stretchesOf` is not changed, and `layers.test.tsx` passes untouched.
- `Layered` gains the standing trails by offset: for each run with `stands` and a `trail`, its end clamped to the
  text (`Math.min(run.end, text.length)`), kept only if the clamped run is not empty. At one offset they are ordered
  by `z` ascending, then by their place in the runs' list.
- `layeredText`, for each piece `[from, to)` of a text node:
  - **a wrap stretch or plain words:** the piece is cut at every standing offset `e` with `from < e < to`, each part
    drawn as the piece was (a wrap run's `render` is called once for each part, keyed `${run.key}@${partFrom}`), and
    the standing trails of `e` are drawn after the part that ends at `e`. Standing trails at `e === to` are drawn
    after the piece.
  - **a replace stretch:** after the run's one `render`, the standing trails of every `e` with
    `st.start < e <= st.end`, in offset order.
  - **the run on top's own trail** is drawn as today, first. A standing run that is itself on top at its end draws
    its trail once, by the standing rule, not twice.
  - A trail's key is `${run.key}~trail`, as today.
- The header of `layers.tsx` (the paragraph beginning "A wrap run may also carry a **trail**") says the new rule and
  keeps the old one for a run that does not stand.

Tests, red first, in the `a wrap run's trail` block, with its `wrapRun` helper given a `stands` argument:

- a standing trail under a higher wrap run that covers its end is drawn, after the higher run's piece that ends at
  that offset, and the higher run's words on either side of it are two pieces whose texts join to the original;
- a standing trail whose end lies inside a higher replace run is drawn right after what the replace run draws, and
  the replace run is drawn once;
- two standing trails at one offset are both drawn, the lower `z` first, then list order; with the top run's own
  ordinary trail at the same offset, that one is first;
- a standing run on top at its own end draws its trail once;
- a standing trail at the end of the text, and one whose end falls where one text node ends and a `[b]` begins, is
  drawn once, inside the formatting of the piece that ends there;
- the four existing "not drawn" and "belongs to the run on top" tests pass unchanged (their runs do not stand).

  words and nothing is played. No `staffConfigs`: a fallback cannot know the post, as Laugh Track's cannot.

## Review focus

- **Acts an instance already holds.** No play of `this` exists anywhere, and the plan changes no stored shape. The
  one change to what existing plays draw is Task 1's cut of a wrap piece at a standing offset: a post with no THIS
  on it must draw byte for byte what it drew (Autocorrect's, Laugh Track's and the spoiler's own tests are the
  watch).
- **A page that never settles.** The gap's height depends on the note's height, the note's place on the gap's box,
  and a `ResizeObserver` watches the wrapper that the gap makes taller. Read the measuring for a loop: it must reach
  a fixed point in one pass and not write a height it has already written. Three notes on a long post beside
  Autocorrect's and Whoops!'s own observers is the case to try by hand.
- **A busy page.** Each note is one phrase search over the post's text at render. A thread page of fifty posts with
  three notes each, on a phone, should scroll as it does without them; the searches must be memoized on the post's
  body and the plays, not run on every render.
- **A mask.** The drawn note, the hidden line, the receipt and the log line name no caster; only the Lens's row
  does. The receipt reads its phrase from the play's own configuration, never from a version another reader could
  not open. A cast's refusals depend on the post's words, the cards on it and a ward, never on who wrote the post.
- **A sprung back.** A set THIS lands on the quoting post with no check by the card's rules (the spring is SQL's).
  If the quoting post is then edited so the phrase is gone, the note is a receipt on it from the start of that
  version; the effect must not assume a wedge ever stood.
- **The author's selection.** Whoops!'s scrub and Graffiti's wall take presses on the body; the drawn note takes
  none and must not swallow one (no handler, and `pointer-events` left to the ink above it).
